# 生姜调研

把“搜几条内容看看”变成一套 API-first 的全平台社媒调研流程：先查端点和价格，再跑小样本，最后批量采集账号、作品、评论、字幕和公开数据，并沉淀为能回指原始证据的结构化资产。

## P0：费用与授权

这个 Skill 采用 MIT 协议免费开源，数据使用第三方 TikHub API。TikHub 是余生姜基于真实调研使用体验主动推荐的网站，余生姜个人认为它非常好用；这不代表 TikHub 官方合作、授权或商务背书，TikHub 不是 Shengjiang 自建、代理或转售的服务。

历史公开量级约 `0.001–0.01 USD / 次`，仅帮助理解，不能当作当次报价。付费调用前读 `references/paid-api-route.md`，按具体端点与请求数查官方价格计算接口、提供费用预览，第三方 ASR 单列。

先跑 1–3 条样本，通过后才批量。先检查已有授权：用户已明确允许相应付费范围和预算时，报告预览与样本结果后继续，不再重复询问；未获付费授权、扩平台/数量/评论深度、增加 ASR 或超预算时，只暂停依赖该授权的部分。用户只说“看看多少钱”时保持估价，不实际采集。

Key 默认保存在 `scripts/.tikhub_api_key`，后续会话直接复用；公开包不预置真实 Key。配置读取与迁移约定保持 `references/configuration.md` 为唯一详细真源。

## P0：视频转写边界

- 公开视频转逐字稿默认走免费路线，不占火山额度：小红书平台字幕（`scripts/xhs_subtitle.py`）→ 必剪云端识别（`scripts/bcut_asr.py`）→ 画面字幕识别（`scripts/screen_subtitle.py`，macOS）。顺序、命令和实测准确度见 `references/free-transcribe.md`；`video_download_transcribe.py` 默认 `--transcribe free` 已自动走前两步。
- 必剪是非官方接口，音频会传到 B 站服务器：只用于公开视频，客户录音、会议录音、内部视频不走这里。
- 火山额度池只在用户当轮明确要求“用火山转”时使用（`--transcribe volc`），凭据与额度见 `references/volc-quota-pool.md`；免费路线失败时不自动切到火山。
- 禁止使用 Whisper、faster-whisper、MLX Whisper 或其他本地语音模型做临时转写或失败兜底；
- 三条免费路线都失败时，保留媒体和元数据，标记“待转写”，在汇报里列出失败条目和原因。
- 用户要求走火山时：只在提交前明确返回时长额度耗尽后切换下一个资源，并停用耗尽入口；处理中的任务不重复提交。没有额度池的旧配置才使用 `_flash` → 标准版的一次兼容回退。

## 能力边界

本 Skill：

- 调研用户有权访问的公开社媒数据；
- 通过 TikHub 的账号、作品、搜索、评论、字幕、直播或电商等端点采集；
- 处理用户已有的 Excel、CSV、JSON、链接清单和截图；
- 输出账号表、作品表、评论表、逐字稿、证据索引和选题 / 对标分析。

本 Skill 不：

- 在公开代码包中预置真实 API Key、免费数据源、Cookie 或平台登录态；用户自己的 Key 可以直接保存在 Skill 内；
- 代表 TikHub、代理或转售 TikHub 服务，或承诺其价格、稳定性和售后；
- 绕过登录、验证码、付费、访问控制或平台限制；
- 自动登录创作者后台抓留存、流量来源等非公开数据；
- 把免费开源 Skill 说成免费 API。

使用本 Skill：

- 全平台调研、博主调研、对标账号、关键词 / 话题调研；
- 拉近 N 条作品、抓评论区、下载公开媒体、取字幕或做逐字稿；

## 标准工作流

### 1. 定义调研任务

从用户当前请求和已有上下文提取；只追问影响对象、费用或范围的缺口：

- 平台、账号 / 链接 / 关键词；
- 时间范围和样本量；
- 账号、作品、评论、字幕、媒体等字段；
- 最终交付物；
- 是否允许 TikHub 付费调用；
- 输出目录。

把任务归为单篇内容、账号批量、关键词 / 话题或对标资产包，避免一上来全抓。

长期产物按目标库写入门禁确定唯一落点：已有项目沿用该项目；无项目的外部输入可进入目标库已声明的资料区，不为了保存结果新建项目。归属尚未确定的小样本只进系统临时目录，不散落知识库根、output 或 outputs。保留可回溯原始证据；缓存与临时链接不成为第二份事实源。

### 2. 查端点

端点不确定时直接查询 TikHub OpenAPI 描述，不先靠网页猜参数：

1. 找账号发现 / 资料端点；
2. 找作品列表和分页字段；
3. 找单条详情、评论和回复端点；
4. 找平台字幕或媒体地址；
5. 记录每个端点的请求方法、单价、每页数据量和限制。

### 视频下载 + 逐字稿快捷模式

用户直接给出公开视频链接并要求“下载视频、转逐字稿、提取原文、准备对标素材”时，不要逐步手工编排详情请求、下载、音频处理和 ASR。完整读取 `references/video-download-transcribe.md`，先 dry-run 显示平台、端点和请求数，再运行：

```bash
python3 scripts/video_download_transcribe.py \
  --url '<公开分享链接>' \
  --out '<项目唯一真源目录>'
```

批量输入使用 `--links-file`。重复运行相同输出目录时，状态为 `done` 的链接必须在付费请求前跳过；只有用户明确要求重跑时才加 `--replace`。标题、简介和普通 `caption` 不得当成平台字幕。

### 3. 估价与小样本

按 `references/paid-api-route.md` 执行具体命令和预览。请求数按账号资料、列表页、详情、评论与楼中楼、字幕等分别拆算，不把“100 条作品”直接当成“100 次请求”。不同端点分别估价后相加，第三方 ASR 单列。

先离线 dry-run，再按有效付费授权执行 1–3 条真实样本。样本需同时满足：对象正确、核心字段齐全、分页与时间和互动口径明确、无权限/余额/限速错误、成本符合预估。失败只修该端点或缩范围，不直接批量重试；通过后沿用已有范围和预算继续。

### 4. 按成本顺序采集

1. 账号资料：昵称、简介、粉丝、主页链接和采集时间；
2. 作品元数据：标题、发布时间、链接和公开互动；
3. 评论：默认每条 1 页顶层评论，确认有价值后再加深；
4. 媒体：封面 / 图片按需下载，视频只在有明确用途时下载；
5. 字幕：走免费路线（平台字幕 → 必剪 → 画面识别），不产生转写费用；用户要求火山时另行估价。

每次批量只在已有授权范围内运行。相同任务继续执行前回读已完成输出与分页状态，避免重抓已完成记录；遇到游标不前进、翻页异常或字段漂移时停止该路，不无限重试。费用超授权预算时暂停并报告。

### 5. 保存原始证据

推荐目录：

```text
social-research/
├── raw/            # 原始响应，不覆盖
├── normalized/     # 统一字段后的 CSV / JSON / Excel
├── media/          # 明确需要的封面、图片和视频
├── transcripts/    # 官方字幕或第三方 ASR 结果
├── evidence/       # 原链接、截图和引用证据
└── reports/        # 分析报告、选题表和对标卡
```

字段标准见 `references/output-schema.md`。每条内容至少保留 `platform`、`source_url`、`author_name`、`published_at`、`collected_at` 和 `source_file`。

### 6. 分析与交付

推荐交付：

- 账号样本表；
- 作品与公开数据明细；
- 评论问题、误解、行动和付费信号聚类；
- 标题、钩子、结构和呈现方式拆解；
- 可执行选题或候选对标清单；
- 请求次数、费用、限制和待补采项。

原始字段与 AI 推导字段分开。结论必须能回指原始链接或文件，不只写“互动很好”“内容不错”。

## 配置只检查一次，失败才排障

需要在线调用时先运行通用或视频脚本的 `--check-config`，只看配置状态与来源，不打印文件内容。已配置直接复用；首次使用、失败或用户要修改配置时再完整读取 `references/configuration.md`。

Key 默认实时读取 `scripts/.tikhub_api_key`，文件优先于环境变量；保留用户自选路径、JSON、旧 `.local/tikhub-api-key`、环境变量和 Keychain 的兼容方式。已有 Key 不反复索取，不因保存位置或权限重复要求配置、迁移或确认。更新时不覆盖用户配置。具体读取顺序与 API Base 只按 configuration 执行。

## 安全与合规

- 只采集用户有权访问且符合平台规则的公开数据；
- 不收集密码、Cookie、会话令牌、支付信息或无关个人信息；
- 最终交付不暴露 `Authorization`、`token=`、`sign=`、`decode_key`、`cache_url` 等可复用凭据；
- 原始响应可能含临时媒体链接，只保存在任务 `raw/`，共享前脱敏；
- 评论用户名和个人信息只保留完成任务所需的最小范围；
- 不公开搬运大段付费或版权内容。

## 错误处理

- 没有 Key：先检查已保存的文件、配置和兼容来源；确实未配置时才说明一次保存步骤，用户已提供 Key 就直接代存。不要把功能偷偷切成另一套手动采集；
- `401`：Key 无效、过期或请求头不正确；
- `402`：余额或额度不足；
- `429`：触发频率限制，降低并发、缩小范围或延迟重试；
- 必剪接口报错或限流：稍后重试一次，再不行改用画面字幕识别，仍不行标“待转写”，不自动切火山；
- 火山 ASR 时长耗尽（仅在用户要求走火山时）：记录具体资源，交给额度池停用并尝试下一项；限流、认证、网络错误不切换，不把单个资源错误扩大为账号整体无额度；
- 成功但无数据：核对目标、地区、权限、时间范围和分页参数；
- 字段漂移：保留原始响应，更新映射，不改写原始数据；
- 三条免费路线都拿不到逐字稿：交付元数据并标“待转写”；
- 成本超预估：立即暂停，重新给请求与费用预览。

## 验收

- 平台、对象、范围、采集时间和数据来源写清楚；
- 样本通过后才批量；
- 实际请求数与费用有记录；
- 原始数据不覆盖，结构化结果可回溯；
- 评论深度和逐字稿来源写清楚；
- 每份逐字稿写清来源（小红书平台字幕、必剪识别、画面识别（未校对）、待转写）；用了火山时，额度、真实测试和失败按资源报告；流式与录音额度分列，按各自协议消费；只有实测通过才启用，不能把已保存配置当成调用成功；
- 最终结果不含密钥、Cookie、登录态或临时下载凭据；
- 没有把计划中的自动化写成已经运行；
- 没有把免费开源 Skill 说成免费 API。

## Examples

输入：`调用 shengjiang-research，抓这个小红书账号近 100 条作品和每条一页评论。`

动作：识别账号 → 查资料 / 作品 / 评论端点与单价 → 拆算成本并报告预览 → 在有效付费授权下采 1–3 条样本 → 样本通过后沿用已授权范围批量 → 输出原始 JSON、结构化表格和评论洞察；缺付费授权时才请求具体授权。

输入：`这个 Skill 免费吗？调研 20 个账号大概要多少钱？`

回答：Skill 代码免费开源，TikHub API 由用户自行付费。先根据每个账号的作品数、评论深度和具体端点拆请求，再调用官方价格计算 API；只给带来源和查询时间的估算，不承诺固定金额。
